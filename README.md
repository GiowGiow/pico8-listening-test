# PICO-8 listening test

Web app and API of the subjective evaluation of the DCC831 (Generative AI for
Music, UFMG, 2026/2) final project, which trains autoregressive models that
compose music for [PICO-8](https://www.lexaloffle.com/pico-8.php).

A participant sees the cartridge of a PICO-8 game and its genre tag, listens to
two 20-second clips, the game's own song and a song generated by the model for
the same tag, and answers which of the two fits the game better.

Adapted from the Humanness Percept study apps by Henrique Sousa
([web](https://github.com/HenriqueDSousa/humanness-percept-web),
[server](https://github.com/HenriqueDSousa/humanness-percept-server)), used in
"Echoes of Humanity: Exploring the Perceived Humanness of AI Music"
([arXiv:2509.25601](https://arxiv.org/abs/2509.25601)), whose protocol this test
follows. The first commit is the import of those two apps; every later commit is
a change made for this study.

## Protocol

- **Pairs.** One game of the frozen test split per pair: its own song against a
  song sampled from the tag-conditioned LSTM (grid_block tokenizer, one control
  token per tag, top-p 0.95) for the same tag. The tag of a game is the first of
  its Lexaloffle BBS tags that the model knows. The generated clip of a pair is
  drawn at random among the samples of that tag, never picked by similarity.
- **Balance.** Four tags (platformer, puzzle, arcade, shmup), 8 games each, one
  song per cartridge. Each participant gets 2 pairs per tag, taken from the
  least-assigned pairs, plus one control pair heard last by everyone (a game's
  song against the Markov baseline): 9 pairs.
- **Clips.** Both clips go through the same synthesizer with no SFX filters, are
  cut to 20 s, normalized to -16 LUFS and encoded as constant-bitrate MP3 under
  random ids. Track order and pair order are random.
- **Questions.** Per pair: a forced choice between track 1 and track 2, whether
  the participant already knew the game or one of the songs, and an optional
  comment. The participant must listen to 15 s of each track first. At the end:
  age, native language, practical and formal musical experience, familiarity
  with AI music and with chiptune.
- **Question mode.** `STUDY_QUESTION` on the server selects the one question of
  the study: `fit` (which song fits the game, the default), `ai` (which one was
  generated by AI) or `preference`. It is stored with every answer.
- **Analysis.** `/admin` reports the share of answers that picked the original
  song (overall, per tag, per pair) with Wilson intervals and an exact binomial
  test against 50%, and exports every answer as CSV for the mixed-effects model.

Each folder has its own README with setup, endpoints and what changed from the
original apps (the date bug, same-origin API, no e-mail stored, rate limits).

## The catalog is not in this repository

`server/catalog/catalog.json` says which clip of each pair is the original, so
it is kept out of the repository while the study is running, together with the
rendered audio and the cartridge images. `server/tools/prepare_pairs.py` builds
all three from the project's data and the samples of the conditioned model.

## Running it

```bash
cd server && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/flask --app app.wsgi run --port 5000     # needs a catalog
cd ../web && npm ci && npm run dev                 # proxies /api to port 5000
```

In production the two containers sit behind one host: the ingress sends `/api/`
to the server and everything else to the web app. `/admin` shows the answer key
and must only be routed on an internal host listed in `ADMIN_HOSTS`.
