# PICO-8 Percept: server

API of the PICO-8 listening test, adapted from
[humanness-percept-server](https://github.com/HenriqueDSousa/humanness-percept-server).
Participants see the cartridge of a PICO-8 game from the test split and hear two
20-second clips: the game's own song and a song generated by the tag-conditioned
model for the same game tag. They answer one question about the pair, set by
`STUDY_QUESTION`: which song fits the game (`fit`, the default), which one was
made by AI (`ai`) or which one they prefer (`preference`). The question is stored
with each answer.

What changed from the original:

- **Dates.** `default=datetime.now()` was evaluated once at import, so every
  answer carried the time the server started. Defaults are now functions
  (`default=utcnow`), and each answer also records `answered_at`.
- **No S3, no AWS credentials.** Clips are served by the API from files baked
  into the image; SQLite on a volume replaces the hard-coded RDS password.
- **Security.** Same-origin API under `/api` (no CORS), participant id derived
  server-side with an HMAC of the e-mail (the address is never stored or sent
  back), ownership check on every answer, write-once answers, input validation,
  16 KB body limit, per-IP rate limits, registration cap, generic error bodies,
  gunicorn instead of the Flask dev server, non-root image. The researcher panel
  at `/admin` shows the answer key, so it only answers on the host names in
  `ADMIN_HOSTS` and the public ingress does not route `/admin` at all.
- **Labels never leave the server.** Clip ids are random and the API returns
  only URLs, so neither the response nor the file name says which clip is
  human; every clip has the same length and file size.

## Layout

| Path | What |
|------|------|
| `app/api.py` | Endpoints under `/api` |
| `app/assignment.py` | Picks each participant's pairs, balancing counts |
| `app/catalog.py` | Loads `catalog/catalog.json` and syncs it into the database |
| `app/export.py` | CSV export of answers |
| `app/admin.py` | Researcher panel: collection, results, catalog checks, pairs |
| `tools/prepare_pairs.py` | Builds the catalog: games, clips and cartridge images |
| `tools/prepare_songs.py` | Rendering helpers (and the catalog of the first design) |

## Endpoints

| Method | Path | Notes |
|--------|------|-------|
| POST | `/api/participants` | `{email, locale}` → `{participant_id, status}` |
| GET | `/api/session` | header `X-Participant-Id`; assigns pairs on first call |
| POST | `/api/responses/<id>` | answer one pair, once |
| PUT | `/api/participants/me` | demographic form, after every pair is answered |
| GET | `/api/audio/<id>.mp3` | clip, with HTTP range support |
| GET | `/api/images/<id>.webp` | cartridge image of a pair |
| GET | `/admin/` | researcher panel, internal hosts only |
| GET | `/admin/answers.csv` | every answered pair |

## Building the catalog

```bash
../TPfinal-music-rn/.venv/bin/python -I tools/prepare_pairs.py --tp-repo ../TPfinal-music-rn \
    --cond-run <results of the tag-conditioned run> --job <job id>
```

Defaults: tags platformer, puzzle, arcade and shmup, 8 games per tag, one song
per cartridge, CC-licensed cartridges first, 20 s clips, seed 831, plus one
anchor pair (a game's song against the group's Markov baseline) that every
participant hears last. Each participant gets `PAIRS_PER_TAG` (2) pairs per tag.
The generated clip of a pair is drawn at random among the samples of the same
tag. Cartridge images come from the Lexaloffle BBS and are cached in `.cache/`.

## Development

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/flask --app app.wsgi run --port 5000
```

## Exporting answers

```bash
kubectl -n pico8-percept exec deploy/server -- python -m app.export > answers.csv
```
